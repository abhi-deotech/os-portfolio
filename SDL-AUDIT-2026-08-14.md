# Lumina OS × SDL — what's still missing

> **STATUS: mostly resolved.** This document was the read-only audit. The fixes landed immediately
> after in the commit that follows it — see the "Resolution" section at the bottom for what was
> fixed, what was deliberately left, and what is still genuinely open. The body below is preserved
> as the original findings so the reasoning behind each fix stays legible.

Full-repo sweep, six parallel research passes (apps batch A/B, shell chrome, theme-engine
internals, in-app content, cross-cutting a11y/motion/density) plus direct verification of the
highest-impact claims. This is the "what needs attention" list; triage and fix ordering came after.

**Scale**: ~180 individual file:line findings across 40+ components. This document groups them by
what actually matters rather than listing all 180 — the raw per-app breakdown is in the appendix.

---

## 0. The one finding that reframes several others

`scripts/denylist.mjs` exports two different things the P0–P8 work seems to have conflated:

- `DENYLIST` — an object with a **reason** per file. This is the actual lint exemption; `token-lint.mjs:48` checks only this (+ `DENY_DIRS`).
- `SHELL` — a bare array, consumed **only** by the codemod under a `--shell` flag, to pick which files an automated pass targets first. Its own comment says why: *"migrated first, because it is the most visible and easiest to verify."*

`ControlCenter.jsx` is in `SHELL`, not in `DENYLIST`. It was never exempt from anything — it was a
priority-one TODO that reads, today, as if it never got finished: 34+ literal neon-hex/rgba sites
(verified directly). `SystemDashboard.jsx` and `SystemMetricsWidget.jsx` are the same story.

This isn't a tooling gap either — I checked `scripts/.token-allowance.json`: ControlCenter carries
a **blessed allowance of 58 hex literals**, i.e. someone ran `--bless` to lock in the backlog
rather than clear it. The ratchet is honest about what it's tracking; it was just never brought to
zero for this file.

**Takeaway**: "shell chrome is migrated" was true for Desktop/Taskbar/Window/Spotlight, not for
ControlCenter/SystemDashboard/SystemMetricsWidget. Those three need the same treatment the other
shell files already got.

## 2. The `bg-white text-sdl-onAccent` contract violation (repeated pattern)

`onAccentInk()` (`registry.js:61-72`) picks ink by **measured contrast against the accent**, not
against white — that was P2's whole fix for Honey Vivid's dark-teal accent. Pairing a literal
`bg-white` with `text-sdl-onAccent` breaks the contract: on any colorway whose `onAccent` resolves
to a light ink (because the accent itself is dark), the text/icon can go invisible on that white
surface.

Confirmed sites: `LoginScreen.jsx:150` (primary "Authenticate" button), `MusicApp.jsx:444,579`
(play/pause — see bug #4 above, compounding it), `TriviaGame.jsx:123,162`. Reported but not
independently verified: `MemoryGame.jsx:196`, `Game2048.jsx:145`.

## 3. Systemic hardcoded-color patterns (visible breakage across colorways)

**The react-contexify context menu is 100% unmigrated.** `src/index.css:247-290` — every rule in
`.os-context-menu.contexify` is a raw literal (`rgba(14,14,22,.75)`, `#a3aac4`, `color: white`,
etc.), never varies with `[data-mode]`, and `App.jsx:188,211` hardcodes `theme="dark"` on top of
it. This menu is every right-click surface in the OS. Under any light colorway it renders as a
fixed near-black panel. One agent independently called this "the single largest theming gap
found" — I agree, it's the highest-leverage single fix in this list (one CSS block, appears
everywhere).

**Nine of ten productivity-app shells hardcode their own near-black background** instead of
`os-surface`/`sdl-plane`, while correctly using SDL roles for their foreground content — a strong
signal these were partially, not fully, swept: `Games.jsx`, `Snake.jsx`, `Sudoku.jsx`,
`TriviaGame.jsx`, `MusicApp.jsx`, `LuminaChat.jsx`, `Notepad.jsx`, `TaskManager.jsx`,
`Achievements.jsx`'s chrome (badges themselves are correctly denylisted). `DocumentationApp.jsx`
is the sole clean exception (one hardcoded pane background aside — its best single fix, see
appendix). Possible alternative reading: several of these share a consistent "always-dark
cyberpunk" identity that might be *intentional*, the way `BSOD.jsx` is — if so it needs its own
denylist entry with a reason, not a silent pass.

**Portfolio apps hardcode panel backgrounds too**, several with raw `rgba()` glows that are
byte-identical to retired legacy hexes (`rgba(0,210,253,.5)` = old `#00d2fd`, etc.):
`AboutMe.jsx`, `Projects.jsx`, `MailApp.jsx`, `AIChat.jsx`, `ControlCenter.jsx` (see §0),
`SystemDashboard.jsx`.

**Two more reincarnations of the retired per-app accent-hex map**, both bypassing `AppIcon`:
- `Projects.jsx:24-113` — each project entry carries its own literal hex (identical to the old
  `legacyHex` values), driving both the icon tile and inline styles directly.
- `Games.jsx:210-239` — the in-app Achievements tab rebuilds a local 4-colour hex map instead of
  using SDL roles or `CustomIcon`.
- `TaskManager.jsx:18-34` — a third, independent hardcoded per-app colour map for the process
  list, which actively **conflicts** with the real per-app `hue` system in `config/apps.jsx`
  (Terminal/Settings/Music get arbitrary unrelated colours here instead of their real dock hue).

**`CustomIcon`'s `glow` prop bypassed with a literal**: `Snake.jsx:208`, `TriviaGame.jsx:119,261`
pass a raw hex/rgba into `glow`, defeating the exact mechanism (`var(--sdl-glow)`) built to make
halos resolve to `transparent` in light mode. These three keep their halo regardless of mode.

## 4. The semantic-status roles exist and are used almost nowhere

`--sdl-alert`/`--sdl-warn`/`--sdl-done` are real, defined roles (`tailwind.config.js`,
`cssVars.js`) — and this was the single most-repeated finding across every survey agent: nearly
every error/success/warning state in the app reaches for stock Tailwind `red-500`/`green-500`/
`yellow-400` instead. Confirmed sites: Sudoku invalid-cell, Trivia wrong-answer + timer,
TaskManager kill/status, Notepad save-success, Mail trash/starred, FileExplorer delete/reset/
storage-sync, Settings Puter-sync status badges, DocumentationApp sync button, LuminaChat/
Achievements connection dots. This is an adoption gap, not a design gap — the roles exist, nothing
reaches for them.

## 5. Theme-engine internals (bugs in `src/theme/` itself)

- **`accentAtLightness()`'s chroma floor** (`registry.js:210`, `Math.max(C, 0.09)`) contradicts
  the honest-greyscale behaviour the icon system (`icons.js`, no floor) correctly implements for
  near-neutral colorways like Mono Soft. Result: the Quantum core / music visualiser show a
  visible tint on a colorway where the icon set correctly shows none — same accent, two different
  answers depending which code path reads it.
- **Duplicate math**: `cssVars.js`'s `accentMetrics()` reimplements `registry.js`'s `saturation()`
  byte-for-byte instead of importing it (both are in the same module's import list already).
  `oklch.js` and `registry.js` also each implement the sRGB companding curve independently, once
  as 0–1 float, once as 0–255 int. Both are drift risks — a fix to one won't propagate.
- **`overrides.js`'s font-override docstring undersells its own scope**: it names Rose Dusk/Garden
  Dawn (Gill Sans rejection) but `normalize()` actually drops `cw.font` for every colorway — 13 of
  15 are silently affected, not the 2 named. The behaviour matches upstream's typography skill, so
  it's not wrong, just underdocumented.
- **`legacy-lumina.js` prose vs. its own `missingRoles` array disagree**: the comment says "no
  sunken", but `sunken` isn't in `missingRoles` (it has a real hex); `chart` is in the array but
  unmentioned in prose. The comment also cites "a Law 4 violation" for `surface === plane`, but
  Law 4 in the vendored tokens is about chart-well demarcation — looks like a mislabeled citation.
- `TOKENS.states` (`STATES` export) is vendored and exported but has zero consumers anywhere —
  unlike `LAWS`/`GLOBAL`, which both surface in the Design Language showcase.

## 6. Density and motion tempo: fully built, barely consumed

- **Density** (`comfortable`/`compact`): the full token set (`--sdl-s1`…`s9`, `--sdl-card-pad`,
  `--sdl-row-pad`, `--sdl-body`, `--sdl-kpi`, `--sdl-control-h`) is real and correctly derived —
  and has **zero consumers outside `src/theme/` itself**, except Settings' own control heights and
  the internal showcase. Toggling Compact changes nothing in any of the 18 real app windows: no
  list row, card, or KPI number moves. It's a fully-built feature with no downstream adopters.
- **Motion tempo** (`cw.tempo.hover/press/pane`): similarly displayed correctly in the showcase,
  essentially unconsumed by real components (most just use fixed framer-motion spring configs).

## 7. Accessibility: the app-content layer has almost no keyboard-focus treatment

Coverage estimate from a ~150-element sample: **~15–20%**, concentrated in exactly five files
(`ControlCenter.jsx`, `Taskbar.jsx`, `settings/Appearance.jsx`, `Window.jsx`, `Desktop.jsx`). Every
actual application — MusicApp, MediaPlayer, PhotoViewer, FileExplorer, Browser, MailApp,
DocumentationApp, both games' D-pads/number-pads, TaskManager — has **zero** `focus-visible`
anywhere. There's no global CSS fallback either (`src/App.css` has one rule but isn't imported by
anything — dead leftover from the Vite template).

Worst instance is finding #7 in §1 above (Games launcher cards, not just unstyled but
unreachable). `Desktop.jsx:64-95` is the reference implementation the rest of the app should be
matching — `role="button"`, `tabIndex={0}`, explicit `onKeyDown`, proper ring.

## 8. Stale in-app documentation

The virtual file system (`src/data/fileSystem.js`) ships three "real" documents a user can open in
Files/Documentation, all describing the **pre-SDL system verbatim**:

- **`STYLING.md`** (worst) — its entire "Color System" section is the old comma-separated
  `--os-primary-rgb: 204, 151, 255` triple (the exact bug the current code's own header comment in
  `index.css` says this format causes), plus a "4 accent color presets" table
  (purple/cyan/magenta/green) that no longer exists, plus `filter: brightness(...)` for the
  brightness slider — replaced by a `body::after` scrim.
- **`ARCHITECTURE.md`** — lists `activeAccent: 'purple'` as the live theming field (it's now a
  migration-only vestige; `colorway` is the real one) and describes persistence as `localStorage`
  (it's IndexedDB via `idb-keyval`, which is *why* `applyTheme.js` needed a synchronous mirror).
- **`README.md`** — "4 accent colors, live wallpapers, glassmorphism" feature line, stale count.

Lower priority: `config.json`/`registry.sys`/`environment.sh` flavour files also say
`theme: "purple"` — decorative easter eggs, not documentation someone would treat as authoritative,
but same root staleness. `TERMINAL.md` was checked and is NOT stale on this axis (its 8 terminal
colour palettes are a real, unrelated, still-current feature).

Process note: `DocumentationApp.jsx`'s "Sync Docs" button pulls these three files fresh from
`raw.githubusercontent.com/abhi-deotech/os-portfolio` — fixing them locally won't stick past a
sync unless the upstream repo copy is also updated.

## 9. Where `sdl-notes.md` itself has drifted from the code

- **Focus-ring alpha**: the note (and `overrides.js`'s DEVIATIONS list) says "~45%" as a single
  number. The code actually has **two**: `.45` in dark mode, `.40` in light
  (`grammar.css:24,48`) — below the "~45–50%" the note claims.
- **Botanical wash coverage**: the note says all four Botanical colorways "ship correct-but-quieter
  with plane + wash only." Checked against the vendored tokens: only **Garden Dawn** actually has a
  `wash` field. Periwinkle Vivid, Emerald Bold, and Orchid Bold have neither `wash` nor `motif` —
  they render **plane only**, flatter than the note describes for 3 of the 4.

- `MusicApp.jsx:276-279` defines its own inline gradient-identity array for genre chips — the same

  Either give it its own denylist entry or move it into `musicData.js`.

# Resolution — 2026-08-14

Everything in §1–§8 is fixed unless listed under "Still open" below. Architectural and shared-file
work was done by hand; the per-app sweep ran as four parallel agents over disjoint file sets, each
followed by an adversarial reviewer reading its own diff.

**Numbers:** hardcoded hexes **370 → 111**, accent-duplicating hexes **138 → 10**, near-black second
ramp **66 → 17**, `bg-black/N` **48 → 15**, untokenized colour sites **613 → 275**, eslint **3 → 0**
(first clean run of the project). Build green, vendored SDL in sync, token-lint no regressions.

### What the adversarial reviewers caught that the editors missed

Worth recording, because it is the argument for the review stage existing at all:

- **A real behaviour regression.** Wiring `onActivate` into react-arborist made a *single* click open
  files and toggle folders, and made a double-click fire twice — because `DefaultRow` already hangs
  `onClick={node.handleClick}` on the treeitem, and `handleClick` calls `activate()`. The keyboard
  path needed enabling; the mouse path was already handled. Fixed with a pointer-origin flag.
- **Two polarity traps.** `shadow-black/50 → shadow-sdl-ink/50` gives a **white** halo in dark mode
  (`ink` is near-white there). And on the Games achievements panel, folding completion onto
  `sdl-done` made the finished row the dullest on the screen — greyer than the three unfinished
  ones, so it read as *disabled*. Law 10's "completed = neutral grey" is about status in a data
  context, where green-beside-red is the anti-pattern; an earned badge is the opposite case.
- **Nested interactive elements.** Adding `role="button"` to a mail row whose star is a real
  `<button>` is invalid ARIA, and the row's unguarded `preventDefault` swallowed the star's own
  Enter/Space — it became mouse-only. Now `role="listitem"` with an `e.target === e.currentTarget`
  guard.
- **Invisible focus rings.** `ring-os-primary/50` on a tile that already carries
  `border-os-primary/30` — same hue, same alpha. On the one control set that previously had *no*
  keyboard path, the ring was the entire point.
- **Halo/fill hue mismatches.** Demoting `glow="#ef4444"` to bare `glow` resolves to `--sdl-glow`,
  which is the *accent* — so a red alert X haloed violet. Conversely, hand-rolled
  `rgb(var(--sdl-accent-rgb) / .2)` shadows are colorway-correct but mode-*blind*, surviving into
  the ten light packs that `--sdl-glow` exists to keep flat.
- **Chrome borrowing the data channel.** `--os-secondary` bridges to `roles.barA`. Law 2 keeps
  chrome and data in separate voices, so four ControlCenter sites were quietly violating it.
- **A pre-existing broken class**: `to-neon-red` — no `neon` key exists in `tailwind.config.js`, so
  that badge faded to transparent rather than to a second stop.

### Deliberately left alone

- **Snake's CRT scanline** (`rgba(255,0,0,.02)` / `(0,255,0,.01)` / `(0,0,255,.02)`) — aperture-grille
  fringing only reads as such with the true primaries. Commented in place so it isn't "fixed" later.
- **LinkedIn brand hexes** in `SocialWidget` (`#0077b5` et al) — third-party identity.
- **The white mount** under the GitHub contribution raster — it hosts an external image drawn for a
  light backing; theming the mount would not retint the image.
- **`config/apps.jsx`'s `legacyHex` values** — they *are* the Lumina Neon icon theme.
- **`index.css`'s `:root` block** — pre-paint fallbacks, regenerated at runtime.
- **Window traffic lights** — deliberate macOS skeuomorphism.

### Still open

1. **`cv` and `skills` are removed, not built.** No component and no data existed; writing a resume
   is not a decision code should make. Re-add the `APPS` entries plus matching
   `WindowContentRenderer` cases once real content exists — the comment marking the spot is in place.
2. **`os-*` bridge sites rose ~80.** Agents reached for the legacy bridge (`bg-os-surface`) where
   `bg-sdl-surface` would do. Functionally identical — the bridge aliases onto SDL roles — but it is
   sideways on the burndown rather than forward. A mechanical follow-up, not a bug.
3. **`text-sdl-onAccent` on non-accent fills.** A handful of `bg-os-secondary` / `bg-os-tertiary`
   buttons pair with `onAccent`, which is measured against the *accent* specifically. These are
   accent-*family* colours so the miss is small, but it is the same class of defect as the
   `bg-white` bug. Either add `onBarA`/`onAInk` roles upstream or restrict the token to accent fills.
4. **Density is still inert** (§6). The tokens are built and correct; nothing outside `src/theme/`
   consumes them. Wiring compact mode into real list rows, cards and KPI blocks is its own pass.
5. **Motion tempo** (`cw.tempo`) likewise remains largely unconsumed by components.
6. **The GitHub doc sync.** `DocumentationApp`'s "Sync Docs" button pulls README/ARCHITECTURE/
   STYLING from `raw.githubusercontent.com/abhi-deotech/os-portfolio`. The local copies are now
   correct, but a sync will overwrite them until the upstream repo is updated too.
7. **`Browser.jsx`'s MEDIA denylist rationale** is a weaker fit than for the other four files in that
   list — it is iframe chrome, not video. Low urgency, worth a second look.
